# Arena Assistant

Hearthstone 闘技場の3択カードを、iPad の画面配信から画像照合で特定するツール。

カード名の OCR は使わない。ゲーム画面に映ったアートが、HearthstoneJSON の
どのカードアートと同一かを直接照合する。

## ファイル

| ファイル | 役割 |
|---|---|
| `build_card_db.py` | カードDBを作る（これだけが作る） |
| `start.py` | 完成したDBで認識する／HTTP API |
| `bench_recognize.py` | 認識方式の比較検証 |
| `arena_assistant.html` | iPad 実運用 |
| `arena_test.html` | PC 検証・デバッグ |
| `arena_features.sqlite3` | 特徴DB（生成物・約35MB） |
| `arena_stage1.cache` / `arena_shape.cache` | 起動高速化キャッシュ（自動生成・消してよい） |
| `arena_pool.json` | アリーナ対象カードと勝率のキャッシュ（自動生成・消してよい） |
| `arena_calibration.json` | カード枠と180°補正の設定（自動生成） |

## 必要なもの

| | PC（DB作成・検証） | iPad a-Shell（運用） |
|---|---|---|
| Python | 3.8 以上 | 3.8 以上 |
| Pillow | 必要 | DB作成時のみ必要 |
| numpy | 認識に必要 | 認識に必要 |

```
pip install Pillow numpy
```

## 1. Windows PC でDBを作る

```
python build_card_db.py
```

HearthstoneJSON からカード一覧とアート画像を取得し、照合用のサムネを
`arena_features.sqlite3` に保存する。7,300枚ほどで **約75秒 / 約35MB**。
同時に、種別ごとのアート窓と可視マスクもカードレンダーから実測する。

主なオプション。

```
python build_card_db.py --workers 16      同時ダウンロード数（既定12）
python build_card_db.py --limit 300       先頭300枚だけ（動作確認用）
python build_card_db.py --locale enUS     カード名を英語にする
python build_card_db.py --src 512x        より大きいアートを使う
python build_card_db.py --rebuild         最初から作り直す
python build_card_db.py --shapes          種別ごとのアート窓だけ作り直す
```

DB に保存するのは**アートのサムネ**と**種別ごとのアート窓・マスク・枠テンプレート**だけ。
切り出し位置は `start.py` が起動時に生成するので、画角の調整をしても DB を
作り直す必要はない。

## 2. 途中で止まったとき

そのまま同じコマンドを実行すれば、登録済みを飛ばして続きから再開する。

```
python build_card_db.py
```

404 などで失敗したカードだけをやり直す場合。

```
python build_card_db.py --retry-failed
```

終了時に 総カード数 / 成功 / スキップ / 失敗 / 処理時間 / DBサイズ が出る。

## 3. サーバを起動する

```
python start.py
```

- 運用 http://localhost:8080/arena_assistant.html
- 検証 http://localhost:8080/arena_test.html

`arena_features.sqlite3` が無い場合、DBの自動構築は**行わない**。
認識APIは 503 と「build_card_db.py を実行してください」を返す。

初回起動時だけ粗特徴量を計算する（数秒）。結果は `arena_stage1.cache` と
`arena_shape.cache` に保存され、2回目以降は即座に立ち上がる。

起動時に HSReplay からアリーナ対象カードと勝率も取得する（約4秒）。
取得結果は `arena_pool.json` に残り、6時間は再取得しない。
取得に失敗しても前回分で動く。どちらも無ければ絞り込みが使えなくなるだけで、認識は動く。

`0.0.0.0` で待ち受けるので、同じネットワークの端末からも開ける。
起動時に LAN の IP を表示する。**認証は無いので信頼できるネットワークでだけ使うこと**。

## 4. PC で arena_test.html を使う

1. 画像をドラッグ＆ドロップ（クリップボードからの貼り付けも可）
2. 入力モードを選ぶ
   - **アート画像1枚** … すでにアート部分だけ切り出した画像（旧方式で照合する）
   - **Arenaスクリーンショット** … 3択が写った画面全体
3. クラスを選ぶ（任意）
4. 照合方式を選ぶ（既定は「種別ごとのアート窓」）
5. 「認識する」

スクリーンショットモードでは、**緑の枠をカード全体に合わせる**。
アートの形はミニオン＝縦長の楕円、呪文＝横長の角丸、武器＝円と種別ごとに
違うので、絵に合わせようとしても合わせようがない。カードの外枠なら種別に
関係なく一意に決まる。枠は多少ずれていてもサーバが枠の絵を手がかりに
合わせ直すので、おおよそで構わない。

認識すると、**実際に照合したアート窓が青い枠**で、マナ結晶が破線で出る。

結果には **Query / Best match / Difference** が同じ大きさで並ぶ。

- Query … 実際に照合した領域を、種別のマスクを掛けて切り出したもの
- Best match … 1位候補のDB側アートを、同じ窓と同じマスクで切り出したもの
- Difference … 明るさを合わせた上での差分（赤いほど不一致）

各候補について 種別 / Final / SSIM / Edge / Color / Pixel を表示する。
これらは**一致度合いであって正解確率ではない**。

同じカードが `CORE_` / `VAN_` など複数の Card ID で DB に入っている。
アートが同一で区別しようがないため、候補一覧では名前でまとめて出す。

判定は次の3通り。

- **一致** … 1位のスコアが十分高く、2位と差がある
- **判定不確実** … 1位と2位が僅差
- **一致するカードを特定できませんでした** … 1位のスコアが低い

## 5. 正解カードを指定してデバッグする

「正解カード」欄にカード名か Card ID を入れて候補から選ぶと、認識後に
各段階での順位が出る。

```
Correct card: シャラドラシル (TTN_003)
Stage 1: Rank 1 / 2184   cutoff 800
Stage 2: Rank 1 / 800
Final:   Rank 1
```

Stage1 で落ちた場合はこう出る。

```
Correct card excluded after Stage 1
Stage 1 rank: 1427 / 2184   cutoff: 800
```

切り分けの指針。

| 症状 | 見るところ |
|---|---|
| Stage1 で脱落する | 粗い絞り込みの問題。`STAGE1_KEEP` を増やす |
| Stage1 は1位付近なのに Final が悪い | 再順位付けの問題。重み `W_*` を見直す |
| 青い枠がアートからズレている | 緑のカード枠がカード全体と合っていない |
| 枠から読んだ種別が違う | 緑の枠を合わせ直す。種別が違うと窓もマスクも違う |
| Query は合っているのに全部低スコア | DB のアートが古い。`--rebuild` |

## 7. iPad a-Shell で起動する

```
cd ~/Documents/arena
python3 start.py
```

Safari で http://localhost:8080/arena_assistant.html を開く。

1. Cast to Browser の IP を入れて「接続」
2. クラスを選ぶ
3. 「判定」

接続後は**1.5秒ごとに画像を自動更新**する。「判定」は必ず最新画像の
取得から始まるので、古い画面で判定されることはない。

操作画面の項目。

| 項目 | 動作 |
|---|---|
| ループ判定（5秒ごと） | ON の間、5秒間隔で自動判定し続ける |
| アリーナ対象のみ | 照合先をアリーナのカードに限定する（既定 ON） |
| 候補をタップ | そのカードに差し替える |
| カード名で検索 | 認識が外れたときに名前で探して差し替える |
| サーバを停止 | a-Shell の Python を終了させる |

判定結果には、特定したカードのアートと、HSReplay の
**引いた時の勝率とピック率**が並ぶ。一致しなかった場合でも候補は表示される。

**緑の枠はカード全体**に合わせる（絵ではなく外周）。判定後に出る
**青い枠が、実際に照合したアート窓**。青い枠が絵に重なっていれば良い。
多少ずれていてもサーバが枠の絵を手がかりに合わせ直す。

numpy が無い場合は認識できない。a-Shell で次を試す。

```
pip install numpy
```

## 認識のしくみ

```
カードレンダーから、種別ごとのアート窓・可視マスク・枠テンプレートを実測
        ↓
アートのサムネ（64×64 グレー + 16×16 カラー）を全カード分DBに保存
        ↓
起動時に「各カードの種別の窓」で切った粗特徴を生成（変種なし）
        ↓
クライアントはカード全体を余白付きで送る
        ↓
サーバが枠テンプレートでカード枠を合わせ直し、ついでに種別も読む
        ↓
Stage1  8×8 グリッド（輝度・エッジ・色）で全カードから800枚に絞る
        ↓
Stage2  40×40 パッチ ＋ 種別ごとのマスクで再順位付け
        SSIM(重み付きz正規化相関) / エッジ相関 / 色差 / 画素差
```

### 種別ごとのアート窓

ゲーム画面に映るアートの形は、カードの種別で違う。

| 種別 | 形 | カードに対する窓 |
|---|---|---|
| MINION | 縦長の楕円 | x 0.250–0.738 / y 0.108–0.492 |
| SPELL | 横長の角丸 | x 0.176–0.801 / y 0.173–0.479 |
| WEAPON | 円 | x 0.234–0.781 / y 0.144–0.466 |
| LOCATION | 横長 | x 0.148–0.840 / y 0.098–0.487 |

全部を同じ長方形で切ると、枠・名前バンド・文字が混ざる。混ざった部分は
どのカードでも同じ見た目なので、**別のカードどうしのスコアを底上げして
1位と2位の差を潰す**。実測ではこれが最大の外れ要因だった。

### 窓とマスクはどうやって決めたか

手で測っていない。`build_card_db.py --shapes` がカードレンダーから実測する。

1. レンダーと素アートを NCC で位置合わせする（一致度 0.95〜0.99）
2. 同じ種別のカードを重ね、画素ごとに「レンダーの値がアートの値と連動するか」
   を相関で測る。枠・名前バンド・文字はカードが変わっても動かないので相関が
   落ち、**アートが見えている画素だけが残る**
3. 残った連結成分の外接矩形が窓、中身が可視マスク
4. レンダーの中央値はアートが消えて枠だけが残るので、**枠テンプレート**として
   一緒に保存する

ローテーションで枠のデザインが変わっても、`--shapes` を流し直せば追従する。

### 設計上の判断

**クエリの種別は当てなくてよい。** DB はカードごとに種別を持っているので、
候補カード自身の種別の窓とマスクで採点すればよい。クエリ側は種別ぶん
（4通り）パッチを用意しておくだけで済む。「先に種別を確定してから絞る」方式だと、
種別を誤った時点で正解が候補から消える。こちらは誤りようがない。

枠テンプレートによる種別判定は行うが、**除外ではなく加点**にとどめる
（マナコストと同じ思想）。実測で誤判定はほぼ出ないが、出たときに正解を
落とさないため。

**カード枠はサーバが合わせ直す。** 手でドラッグした枠は必ずずれる。
枠の絵はカードが変わっても動かないので、そのままテンプレートとして使える。
クライアントは枠のまわりに 15% の余白を付けて送り、サーバが位置・大きさを
詰める。この自動補正が無いと、枠を 5% 外しただけで Top1 が 100% → 52% に落ちた。

**変種の総当たりは要らなくなった。** 幾何が実測で決まっているので、
旧方式の 37 変種は不要。Stage1 は1カード1特徴で済み、粗特徴は 32MB → 2.3MB、
照合も速くなった。校正の残りずれだけ Stage2 で小さく（27通り）吸収する。

**マナコストは加点に使わない。** 清潔なレンダーなら 96% 読めるが、実機相当まで
情報量を落とすと採用率 35% / 誤読 11% まで落ちる。アート照合だけで Top1 100% に
届いている今、1割誤る +0.03 の加点は足を引っ張るだけ。読めた値は表示にだけ使う。

**MobileNet などの分類embeddingは使わない。** 必要なのは「意味的に似た画像」ではなく
「同一画像」の特定。色や構図が似た別カードを高スコアにしてしまう。

### 実測

`bench_recognize.py` は、カードレンダーを実機くらいの大きさまで落としてから
切り出して照合する。素のアート画像どうしを比べると精度は出て当たり前で、
実機とはかけ離れるため。

条件：1280×960 の疑似画面にカードを 194px で配置、ぼかし 1.0px、JPEG 品質 45、
傾き ±1.5°、明るさのむら、枠ずれ 3%。DB 7,374枚・全クラス・150枚で試行。

| 方式 | Top1 | Top3 | 1枚あたり |
|---|---|---|---|
| 長方形ひとつ（従来） | 26.0% | 28.0% | 201 ms |
| 種別ごとのアート窓 | **99.3%** | **100%** | **146 ms** |

種別判定は 138 正解 / 1 誤り / 11 判定せず。

画面上のカードの大きさと枠ずれを変えた場合（各100枚）。

| カードの高さ | アート窓の幅 | 枠ずれ | Top1 |
|---|---|---|---|
| 300px | 96px | 2% | 100% |
| 194px | 62px | 5% | 100% |
| 140px | 45px | 5% | 100% |
| 100px | 32px | 8% | 100% |
| 70px | 22px | 5% | 97% |
| 194px（ぼかし2.5px / JPEG25） | 62px | 10% | 97% |

```
python bench_recognize.py --n 150
python bench_recognize.py --n 100 --card-h 100 --blur 2.0 --jpeg 30 --miscal 0.08
python bench_recognize.py --n 100 --methods shape
```

レンダーは `_bench_cache/` に残るので、2回目以降はネットワークを使わない。

**これは合成画像での相対比較**であって、実機の保証ではない。実機の
スクリーンショットを `arena_test.html` に入れて確認すること。

## クラスの絞り込み

ヒーロークラスを選ぶと、次のカードが候補に残る。

- そのクラスのカード
- NEUTRAL のカード
- `classes` にそのクラスを含むマルチクラスカード

## アリーナ対象への絞り込み

「アリーナ対象のみ」を ON にすると、照合先が大幅に減る。

| クラス | 絞り込み OFF | 絞り込み ON |
|---|---|---|
| 全クラス | 7351 枚 | 1057 枚 |
| パラディン | 2618 枚 | **299 枚** |

対象カードの判定には HSReplay の統計 API を使う。

```
https://hsreplay.net/api/v1/arena/card_stats/free/?ArenaTimestampRangeFilter=LAST_7_DAYS
```

**これは公式のローテーション表ではなく、直近7日間の実対戦に登場した
カードの集合**。ローリング集計なので、ローテーションが変わっても最長で7日で
自動に追従する。手動でセット一覧を管理する必要はない。

知っておくべき制約。

- 集計は **アンダーグラウンド・アリーナ固定**。無料エンドポイントでは変更できない
- 実測値なので、理論上は「プールにあるが誰も引かなかったカード」が漏れうる。
  ただし 1日で1078枚、7日で1080枚と差がほぼ無く、実害は見られない
- 絞り込んだ結果が 0 枚になる場合は絞り込まない

チェックを外せば従来どおり DB 全体から探す。

## うまくいかないとき

**「arena_features.sqlite3 がありません」** … `build_card_db.py` を実行する。

**HTTP 405 / 404 になる** … ページを `start.py` 以外で開いている。
VS Code の Live Preview や Live Server、`file://` だと HTML は表示されるが
認識 API に届かない。必ず `http://localhost:8080/arena_test.html` で開くこと。

**「numpy が必要です」** … `pip install numpy`。

**Cast画面が出ない** … IP を確認する。サーバが `/castframe` で中継するので、
iPad と配信元が同じネットワークにいる必要がある。

**全部「特定できませんでした」になる** … カード枠がずれている可能性が高い。
`arena_test.html` にスクリーンショットを入れて、青い枠（実際に照合した範囲）と
Query 画像を見る。絵以外が写っていたら緑の枠をカード全体に合わせ直す。

**種別ごとのアート窓がありません** … `python build_card_db.py --shapes` を実行する。

**Query は合っているのに当たらない** … DB のアートが古い可能性がある。
`python build_card_db.py --rebuild` で作り直す。

**遅い** … `STAGE1_KEEP` を減らす。精度と引き換えに速くなる。
